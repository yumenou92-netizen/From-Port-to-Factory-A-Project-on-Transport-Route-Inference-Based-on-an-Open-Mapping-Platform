# 最后一公里汽运计费规则算法设计（修订版）

## 一、算法目标

本模块用于计算任意两个运输节点 A、B 之间的汽运费用和预计行驶时间。

虽然当前主要用于“南方港口—客户工厂”或“中转港—客户工厂”的最后一公里运输，但费用计算模块本身不限定业务阶段，只接收：

- 起点 A；
- 终点 B；
- 订单信息；
- 已知运价数据；
- 节点坐标数据；
- 地图路线数据。

最终输出一条或多条可进入路径规划模型的汽运候选边，每条边分别包含：

- 起点和终点；
- 驾车距离；
- 预计行驶时间；
- 运输总费用；
- 费用来源；
- 距离和时间来源；
- 所采用的计费规则；
- 是否可直接参与路径推荐。

当前项目已经实现“已知汽运路线使用维护运价，未知路线暂转人工确认”的基础安全逻辑。未知线路规则在完成距离服务接入、业务验收和单元测试前，应保持禁用。

---

## 二、核心变量和单位定义

设：

| 符号 | 含义 | 单位 |
|---|---|---|
| \(x\) | A、B 两点之间的实际汽车行驶距离 | 千米 |
| \(t\) | 对应驾车路线的预计行驶时间 | 小时 |
| \(p(x)\) | 当前距离条件下的单吨汽运费 | 元/吨 |
| \(T\) | 当前订单货物重量 | 吨 |
| \(Y\) | 当前订单该汽运段的总费用 | 元 |

原设计中将 \(y\) 定义为“元/吨/千米”，但给出的阶梯公式实际计算的是“当前线路的单吨总运费”，单位应为“元/吨”。

因此，本设计统一使用：

\[
p(x)=\text{当前距离对应的单吨运费，单位为元/吨}
\]

总费用计算公式为：

\[
Y=p(x)\times T
\]

不能再乘一次距离，即不能写成：

\[
Y=x\times p(x)\times T
\]

否则会重复计算距离。

## 三、总体算法流程

```text
输入 A 点、B 点、订单货物信息
              ↓
标准化 A、B 节点名称和 node_id
              ↓
检索已知汽运线路运价
              ↓
是否找到适用于当前订单的有效已知运价？
       ┌───────────────┴───────────────┐
       │                               │
      是                              否
       │                               │
选择最新有效运价               进入陌生线路测算
       │                               │
按价格单位计算总费用           获取 A、B 坐标
       │                               │
取得或补充行驶时间             调用驾车路线 API
       │                               │
生成已知线路候选边             保留有效路线方案
                                       │
                               按阶梯规则计算费用
                                       │
                               生成陌生线路候选边
       └───────────────┬───────────────┘
                       ↓
分别提供 cost 和 time 权重
                       ↓
进入成本最低和时效最优路径搜索
```

## 四、第一层判断：是否为已知汽运线路

### 4.1 已知线路的定义

不能只根据 A、B 名称判断。一条运价记录应同时满足：

1. 始发节点与 A 一致；
2. 到达节点与 B 一致；
3. 方向一致，A→B 与 B→A 默认视为不同线路；
4. 运输方式属于汽运；
5. 包装方式适用于当前订单；
6. 货物品种适用于当前订单；
7. 运价处于有效状态；
8. 运价的费用单位能够与订单数量单位匹配。

建议匹配键为：

```text
origin_node_id
destination_node_id
transport_mode
package_type
commodity
price_type
price_unit
```

### 4.2 同一路线存在多条运价

若找到多条符合条件的运价：

1. 排除失效记录；
2. 按维护日期降序排序；
3. 采用维护日期最新的运价；
4. 若最新日期仍有多条冲突记录，则转人工确认，不应任意选择第一条。

建议选择顺序：

```text
符合业务条件
→ 维护日期最新
→ 价格来源优先级
→ 仍冲突则人工确认
```

### 4.3 已知线路总费用计算

#### 情况一：单价

例如运价为：

```text
40 元/吨
```

订单为：

```text
500 吨
```

则：

\[
Y=40\times500=20000\text{ 元}
\]

#### 情况二：总价

例如运价记录为：

```text
total_price = 30000 元
```

则：

\[
Y=30000\text{ 元}
\]

不能再次乘货量。

#### 情况三：按车、按箱、按柜

只有在订单中存在对应数量时才能计算。

例如：

```text
700 元/箱 × 20 箱 = 14000 元
```

若订单数量为吨，而运价为元/箱，系统不得自动换算，除非存在经过业务确认的“吨—箱”转换规则。

### 4.4 已知线路的时间处理

已知运价表可能只有费用和距离，不一定有行驶时间。因此时间应独立处理：

- 若已知线路表有可靠时间，直接采用；
- 若只有距离，可以调用驾车路线接口补充时间；
- 若接口不可用，则该边可以参与成本搜索，但不能作为可靠的时效搜索边；
- 不得把缺失时间默认为 0。

## 五、第二层判断：陌生汽运线路

若已知运价表中不存在适用的 A→B 汽运记录，则进入陌生线路流程。

### 5.1 坐标获取优先级

按以下顺序获取 A、B 坐标：

```text
标准节点注册表
→ 本地地点经纬度数据
→ 地图地址解析 API
→ 人工确认
```

#### 第一步：查询标准节点注册表

优先根据 `node_id` 查询，不建议每次直接用地点文本匹配。

节点注册表应负责：

- 地点名称标准化；
- 别名识别；
- 坐标冲突检查；
- 名称到标准 `node_id` 的映射。

#### 第二步：查询本地坐标表

若标准节点中已有经纬度，直接采用。

数据来源示例：

```text
地点经纬度.json
```

#### 第三步：地图地址解析

若本地没有坐标，则调用腾讯地图地址解析接口。

查询参数应尽量包括：

- 地点完整名称；
- 详细地址；
- 所属城市；
- 所属省份。

如果只使用简称，且接口返回多个位置，则进入人工确认，不能自动选取第一个结果。

#### 第四步：缓存新坐标

地图查询得到的新坐标不应直接覆盖原始业务文件。

建议写入：

```text
output/geocode_cache.jsonl
```

经过人工确认后，再合并进正式节点库。

---

## 六、驾车距离和时间获取

坐标确定后，调用腾讯地图驾车路线接口，获取 A→B 的汽车行驶路线。

必须获取：

- 实际驾车距离；
- 预计行驶时间；
- 路线标识或路线序号；
- 查询时间；
- 数据来源。

不能使用两点直线距离作为最终汽运计费距离。直线距离只可以用于 API 调用前的候选节点初筛。

### 6.1 地图返回多条路线时的处理

不能分别取所有路线中的最短距离和最短时间，然后组合为一条虚构路线。

例如：

| 路线 | 距离 | 时间 |
|---|---:|---:|
| 路线 1 | 80 km | 100 分钟 |
| 路线 2 | 85 km | 80 分钟 |

错误做法：

```text
距离 = 80 km
时间 = 80 分钟
```

现实中并不存在这条路线。

正确方案是保留独立候选路线：

```text
边 1：80 km，100 分钟
边 2：85 km，80 分钟
```

边 1 可能更适合成本最低搜索；边 2 可能更适合时效最优搜索。

因此，后续图结构适合采用 `MultiDiGraph`，允许同一 A→B 节点对之间保留多条平行运输边。

若业务不希望保留过多路线，可以只保留：

- 距离最短路线；
- 时间最短路线。

若两者相同，则只保留一条。

## 七、陌生汽运线路阶梯计费函数

### 7.1 修正后的单吨运费函数

设实际驾车距离为 \(x\)，单位千米。

单吨运费 \(p(x)\)，单位元/吨：

\[
p(x)=
\begin{cases}
15, & 0<x\leq20\\[4pt]
20, & 20<x\leq30\\[4pt]
20+0.7(x-30), & 30<x\leq100\\[4pt]
69+0.6(x-100), & 100<x\leq150\\[4pt]
99+0.5(x-150), & 150<x\leq250\\[4pt]
149+0.3(x-250), & x>250
\end{cases}
\]

总费用为：

\[
Y=p(x)\times T
\]

其中：

- \(x\)：实际驾车距离，千米；
- \(p(x)\)：该距离对应的单吨运费，元/吨；
- \(T\)：货物重量，吨；
- \(Y\)：订单该运输段总费用，元。

### 7.2 各区间说明

| 距离范围 | 单吨运费计算 |
|---|---|
| \(0<x\leq20\) | 15 元/吨 |
| \(20<x\leq30\) | 20 元/吨 |
| \(30<x\leq100\) | 前 30 公里按 20 元/吨，超过部分按 0.7 元/吨·公里增加 |
| \(100<x\leq150\) | 100 公里时为 69 元/吨，超过部分按 0.6 增加 |
| \(150<x\leq250\) | 150 公里时为 99 元/吨，超过部分按 0.5 增加 |
| \(x>250\) | 250 公里时为 149 元/吨，超过部分按 0.3 增加 |

这里的 0.7、0.6、0.5、0.3 是“超出当前分界点后的边际增加费率”，并不是全程重新乘以距离。

### 7.3 边界连续性检查

| 距离 | 单吨运费 |
|---:|---:|
| 20 km | 15 元/吨 |
| 略大于 20 km | 20 元/吨 |
| 30 km | 20 元/吨 |
| 100 km | 69 元/吨 |
| 150 km | 99 元/吨 |
| 250 km | 149 元/吨 |
| 300 km | 164 元/吨 |

30、100、150、250 公里的区间均保持连续。

20 公里处存在从 15 元到 20 元的阶梯跳升。该跳升可解释为两档起步价，因此可以保留；若业务不希望跳变，需要另行调整。

## 八、费用和时间必须分别作为图权重

每条汽运候选边至少应包含：

```python
{
    "cost": 当前订单该运输段总费用,
    "time_hours": 对应路线的预计行驶时间
}
```

成本最低搜索使用：

```text
weight = cost
```

时效最优搜索使用：

```text
weight = time_hours
```

不能将费用和时间简单合并成一个值，也不能因为使用距离计算费用，就用距离直接替代耗时。

## 十、模块拆分建议

不要把全部逻辑写在一个函数中。

### 10.1 已知线路选择器

```text
TruckRateSelector
```

负责：

- 匹配 A→B；
- 判断包装和品种；
- 过滤失效运价；
- 选择最新运价；
- 发现冲突时转人工确认。

### 10.2 坐标服务

```text
GeocodingProvider
```

负责：

- 查询本地坐标；
- 调用地图地址解析；
- 返回坐标及来源；
- 管理查询缓存。

### 10.3 驾车路线服务

```text
DrivingRouteProvider
```

负责：

- 调用腾讯地图；
- 返回多条完整路线；
- 不负责计算费用。

### 10.4 陌生线路计费器

```text
UnknownTruckCostCalculator
```

只接收：

```text
distance_km
quantity_tons
```

输出：

```text
单吨运费
总费用
计算明细
```

它不应直接调用地图 API。

### 10.5 汽运费用协调器

```text
LastMileTruckCostService
```

负责整体判断：

```text
先查已知运价
→ 未命中再查坐标和驾车路线
→ 调用阶梯计费器
→ 生成候选边
```

## 十一、核心伪代码

```python
def build_truck_edge_candidates(
    origin,
    destination,
    request,
    rate_selector,
    node_registry,
    geocoding_provider,
    driving_route_provider,
):
    # 1. 优先查询已知线路
    known_rate_result = rate_selector.find_latest_applicable_rate(
        origin_node_id=origin.node_id,
        destination_node_id=destination.node_id,
        package_type=request.package_type,
        commodity=request.commodity,
    )

    if known_rate_result.status == "valid":
        total_cost = calculate_known_rate_total_cost(
            rate=known_rate_result.rate,
            request=request,
        )

        time_result = resolve_known_route_time(
            rate=known_rate_result.rate,
            origin=origin,
            destination=destination,
            driving_route_provider=driving_route_provider,
        )

        return [
            create_known_truck_edge(
                origin=origin,
                destination=destination,
                total_cost=total_cost,
                time_result=time_result,
                rate=known_rate_result.rate,
            )
        ]

    if known_rate_result.status == "conflict":
        return manual_review_result(
            reason="同一线路存在多条无法自动判定的有效运价。"
        )

    # 2. 陌生线路：获取坐标
    origin_coordinates = resolve_coordinates(
        node=origin,
        registry=node_registry,
        geocoding_provider=geocoding_provider,
    )
    destination_coordinates = resolve_coordinates(
        node=destination,
        registry=node_registry,
        geocoding_provider=geocoding_provider,
    )

    if not origin_coordinates.confirmed or not destination_coordinates.confirmed:
        return manual_review_result(
            reason="起点或终点坐标无法可靠确认。"
        )

    # 3. 查询完整驾车路线
    route_options = driving_route_provider.get_routes(
        origin_coordinates,
        destination_coordinates,
    )

    route_options = select_distance_and_time_candidates(route_options)

    # 4. 每条路线分别计算费用
    candidates = []

    for option in route_options:
        unit_price = calculate_unknown_truck_unit_price(
            distance_km=option.distance_km
        )

        total_cost = unit_price * request.quantity_tons

        candidates.append(
            TruckEdgeCandidate(
                edge_id=make_edge_id(option),
                from_node_id=origin.node_id,
                to_node_id=destination.node_id,
                distance_km=option.distance_km,
                time_hours=option.duration_hours,
                total_cost_yuan=total_cost,
                cost_rule_id="unknown_truck_bulk_distance_tier_v2",
                price_source="陌生汽运阶梯规则",
                distance_source="腾讯地图驾车路线",
                time_source="腾讯地图驾车路线",
                is_known_route=False,
                is_available=True,
            )
        )

    return candidates
```

陌生线路费用函数：

```python
def calculate_unknown_truck_unit_price(distance_km: Decimal) -> Decimal:
    x = distance_km

    if x <= 0:
        raise ValueError("运输距离必须大于 0")

    if x <= 20:
        return Decimal("15")

    if x <= 30:
        return Decimal("20")

    if x <= 100:
        return Decimal("20") + (x - Decimal("30")) * Decimal("0.7")

    if x <= 150:
        return Decimal("69") + (x - Decimal("100")) * Decimal("0.6")

    if x <= 250:
        return Decimal("99") + (x - Decimal("150")) * Decimal("0.5")

    return Decimal("149") + (x - Decimal("250")) * Decimal("0.3")
```

总费用：

```python
def calculate_unknown_truck_total_cost(
    distance_km: Decimal,
    quantity_tons: Decimal,
) -> Decimal:
    if quantity_tons <= 0:
        raise ValueError("货物重量必须大于 0")

    unit_price = calculate_unknown_truck_unit_price(distance_km)

    return unit_price * quantity_tons
```

## 十二、异常和停止条件

以下情况不得自动形成可用运输边：

- A 或 B 无法匹配标准节点；
- 地图返回的位置存在明显歧义；
- 地图 API 调用失败且没有缓存结果；
- 驾车距离为 0 或负值；
- 订单重量缺失或不为吨；
- 已知运价单位与订单数量单位不匹配；
- 同一路线存在多条最新冲突运价；
- 已知线路没有时间，而系统又要输出时效最优路径；
- 地图路线返回的数据不完整；
- 业务规则版本未启用。

这些情况应输出：

```text
manual_review
```

而不是把费用或时间默认设为 0。

## 十三、必须编写的单元测试

### 13.1 阶梯边界测试

| 输入距离 | 预期单吨运费 |
|---:|---:|
| 10 | 15 |
| 20 | 15 |
| 20.01 | 20 |
| 30 | 20 |
| 31 | 20.7 |
| 100 | 69 |
| 150 | 99 |
| 250 | 149 |
| 300 | 164 |

### 13.2 总费用测试

500 吨、100 公里：

\[
69\times500=34500
\]

500 吨、300 公里：

\[
164\times500=82000
\]

### 13.3 已知线路测试

- 有一条有效记录；
- 有多条记录，选择维护日期最新；
- 最新日期存在冲突，转人工确认；
- A→B 有运价但 B→A 没有，不得反向复用；
- 包装不匹配；
- 品种不匹配；
- 元/吨与吨匹配；
- 元/箱与吨不匹配。

### 13.4 地图多路线测试

确保：

- 距离最短和时间最短路线作为独立候选；
- 不会拼接不同路线的距离和时间；
- 相同路线不会重复生成两条边。

## 十五、最终算法口径

本次修订后的关键结论如下：

1. 已知线路优先采用最新有效维护运价；
2. 未知线路才调用地图获取真实驾车距离；
3. 地图返回的不同路线必须作为独立候选；
4. 阶梯函数计算的是“单吨总运费”，不是“元/吨/公里费率”；
5. 总费用公式为：

\[
Y=p(x)\times T
\]

6. 250 公里以上采用连续增量公式：

\[
p(x)=149+0.3(x-250)
\]

7. 运费和耗时分别进入路径模型，不能混为一个权重；
8. 在地图 Provider、最新运价选择和单元测试完成前，陌生线路规则继续保持禁用。
