# 01 项目背景与需求理解

## 1. 项目背景

现有简易费用测算工具主要依赖后台提前维护节点间运费标准。若路线未维护，则无法计算费用；同时旧工具只能对单一路线测算，无法自动输出多套运输方案。

领导提出的新需求是开发“多方案智能路径规划功能”，系统需要基于物流节点、客户节点、运输方式、费用规则和时效规则，自动生成可选运输路径，并输出成本最低方案与时效最优方案。

## 2. 核心业务链条

完整链条为：

```text
北方港口 → 干线运输 → 南方港口 → 最后一公里 / 末端运输 → 客户工厂
```

其中：

- 北港到南港：干线运输，路径相对固定，主要是运输方式选择；
- 南港到客户工厂：最后一公里，路径复杂，是本项目路径推断模型的重点。

## 3. 第一阶段建议范围

第一阶段建议优先实现：

- 散船干线费用测算；
- 南港到客户工厂的末端路径生成；
- 客户是否有自建码头的路径判断；
- 最近公共码头逻辑的原型；
- 铁路费用模型字段预留与计算规则细化；
- 成本最低方案与时效最优方案输出。

铁路和集装箱可以先做结构预留，不建议第一阶段承诺完整上线。

## 4. 输出目标

系统应输出：

1. 成本最低方案；
2. 时效最优方案；
3. 每条方案的节点链路；
4. 每段运输方式；
5. 每段费用；
6. 每段时效；
7. 费用来源：公式、台账、线下询价、估算；
8. 是否存在缺失数据。
