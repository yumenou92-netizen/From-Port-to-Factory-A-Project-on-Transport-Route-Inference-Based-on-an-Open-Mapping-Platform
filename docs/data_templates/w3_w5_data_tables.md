# W3/W5 数据表模板说明

Updated: 2026-07-28

本文档说明阶段 18 W3/W5 的最小可维护数据结构。模板文件仅使用虚构示例，不包含真实业务明细；正式数据应放入本地 `DATA_DIR` 指向的真实数据目录，例如 `data_REAL/` 或其子目录，且不得提交 Git。

## 1. 文件放置与读取规则

当前代码会在 `DATA_DIR` 下递归查找以下文件名：

| 文件名 | 作用 |
|---|---|
| `港口能力表.csv` | 维护港口/码头节点能否承接散船干线、内河驳船，以及支持的包装和品种 |
| `区域映射表.csv` | 维护城市、港区、港口关键词到散船费率目的组、纯航行时效分区和内河区域的映射 |
| `南港码头作业费.csv` | 维护南港汇总“码头作业费”费率；当前散粮使用 `元/吨`，集装箱预留 `元/箱` |
| `内河驳船运输费率.csv` | 维护内河驳船航费，按起终区域、包装、品种、贸易类型和精确计费单位匹配 |
| `内河驳船运输时效.csv` | 维护内河驳船完整运输段时效，按起终区域和方向匹配 |
| `集装箱船运价时效.csv` | 预留北港—南港集装箱船的精确 OD 运价与航运总时效；首轮只读审计 |
| `部分码头标签.json` | 领导提供的部分码头散粮服务费规则候选源；当前只读审计，不自动写入正式表 |

读取规则：

- 编码支持 `utf-8-sig` 和 `gb18030`；
- 同名文件只能存在一个；若 `DATA_DIR` 下存在多个同名文件，程序会要求人工明确来源；
- `节点ID/标准节点ID` 可为空；为空时，加载器会尝试按名称匹配现有节点注册表；
- 不确定的能力字段必须留空并标为 `manual_review`，不得填 `否`；留空表示“未知”，`否`只表示已经确认“不支持”；
- `吨`、`箱`、`柜` 不做自动换算；W5 当前只接受 `元/吨` 和 `元/箱`，且必须与订单数量单位精确匹配；
- 多值字段可用 `；`、`;`、`，`、`,`、`、`、`|` 或 `/` 分隔。

## 2. 港口能力表

模板：`docs/data_templates/港口能力表.example.csv`

推荐字段：

| 字段 | 类型 | 是否必填 | 说明 |
|---|---:|---:|---|
| `标准节点ID` | 文本 | 否 | 已知标准节点 ID；为空时按港口名称匹配 |
| `港口名称` | 文本 | 是 | 标准港口/码头名称 |
| `区域编码` | 文本 | 否 | 与区域映射表的 `区域编码` 对应 |
| `基础设施类型` | 文本 | 是 | 例如 `seaport`、`river_port`、`rail_station`、`factory_terminal` |
| `可接收北港散船` | 布尔/空 | 否 | 已确认时填是/否；未知必须留空 |
| `是否中转港` | 布尔/空 | 否 | 节点是否可作为运输子路径的中间港口；未知留空。该字段不等同于海港/内河港，也不单独证明存在运输边 |
| `可生成内河驳船边` | 布尔/空 | 否 | 已确认时填是/否；未知必须留空 |
| `支持包装方式` | 列表/空 | 否 | 例如 `散粮`、`集装箱`；未知留空 |
| `支持品种` | 列表/空 | 否 | 例如 `玉米；小麦`；不限定填 `*`，未知留空 |
| `支持运输方式` | 列表/空 | 否 | 只维护影响构边的方式，如 `散船；驳船；汽运` |
| `城市` | 文本 | 否 | 标准市域标签，不用于自动推断作业费区域 |
| `航运时效区` | 文本 | 否 | 已确认的航运时效分区 |
| `确认状态` | 文本 | 是 | `confirmed` 或 `manual_review` |
| `维护日期` | 日期/文本 | 否 | 数据维护日期 |
| `别名` | 列表 | 否 | 已确认的简称/旧称 |
| `数据来源` | 文本 | 是 | 维护来源，例如 `manual_confirmed` |

布尔值可填：`是/否`、`true/false`、`1/0`、`支持/不支持`。

## 3. 区域映射表

模板：`docs/data_templates/区域映射表.example.csv`

推荐字段：

| 字段 | 类型 | 是否必填 | 说明 |
|---|---:|---:|---|
| `区域编码` | 文本 | 是 | 稳定区域编码，用于港口能力和内河规则关联 |
| `区域名称` | 文本 | 是 | 面向业务展示的区域名 |
| `城市关键词` | 列表 | 是 | 用于所在地或城市级匹配的关键词 |
| `港口关键词` | 列表 | 是 | 用于港口/港区名称匹配的关键词 |
| `散船目的组` | 文本 | 否 | 对应散船运价表的目的地列组，例如 `珠三角`、`漳州`、`秀屿` |
| `纯航行时效分区` | 文本 | 否 | 对应领导确认的纯航行时效分区，例如 `福建`、`广西` |
| `作业费区域编码` | 文本 | 否 | W5 人工维护的 `operation_fee_region_code` |
| `作业费区域港口节点ID` | 列表 | 条件必填 | 该作业费区域包含的标准港口 `node_id`；不接受名称或坐标自动推断 |
| `作业费映射依据` | 文本 | 条件必填 | 人工确认依据 |
| `作业费映射规则编号` | 文本 | 条件必填 | 稳定规则编号 |
| `作业费映射规则版本` | 文本 | 条件必填 | 规则版本 |
| `作业费映射确认状态` | 文本 | 条件必填 | 只有 `confirmed` 映射可用于地域代理 |
| `数据来源` | 文本 | 是 | 维护来源 |

注意：人工维护的 `operation_fee_region_code` 仍是优先代理依据。领导展示模式在缺少该映射时，允许由可追溯业务区域解析器确定目标港与参考港同属一个业务区域，再从该区域内具有坐标且适用当前订单的正式费率中选取地理距离最近者。该结果必须标记为 `regional_proxy`，不得描述成目标港精确真实费率；区域无法唯一判断、坐标缺失、费率重复或订单维度不匹配时仍进入人工复核。

## 4. 南港码头作业费表

模板：`docs/data_templates/南港码头作业费.example.csv`

推荐字段：

| 字段 | 类型 | 是否必填 | 说明 |
|---|---:|---:|---|
| `标准节点ID` | 文本 | 否 | 已知标准节点 ID；为空时按南港名称匹配 |
| `南港名称` | 文本 | 是 | 适用南港 |
| `包装方式` | 文本 | 是 | 第一版主要为 `散粮` |
| `贸易类型` | 文本 | 是 | `内贸` 或 `外贸`；当前 Demo 默认 `内贸`，但数据结构保留外贸 |
| `费用类型` | 文本 | 是 | 第一版固定为 `码头作业费` |
| `单价` | Decimal | 是 | `chargeable` 必须大于 0；`not_applicable` 必须为 0 |
| `费用单位` | 文本 | 是 | 散粮为 `元/吨`；集装箱预留 `元/箱` |
| `适用状态` | 文本 | 否 | 默认 `chargeable`；客户自有码头等经确认无需作业费时填 `not_applicable` |
| `不适用原因` | 文本 | 条件必填 | `not_applicable` 必须填写可追溯业务原因 |
| `来源类型` | 文本 | 否 | 正式数据填 `real_data`；演示占位由代码显式 Provider 生成，不建议写入正式表 |
| `适用品种` | 列表 | 否 | 不限定时填 `*` |
| `别名` | 列表 | 否 | 已确认别名 |
| `维护日期` | 日期/文本 | 否 | 维护日期，当前仅保留追溯 |
| `作业费区域编码` | 文本 | 否 | 若该费率可作为地域代理参考费率，则必须填写 |
| `是否地域代理参考码头` | 布尔 | 否 | `是`时必须同时具有标准节点 ID 和作业费区域编码 |
| `数据来源` | 文本 | 是 | 维护来源 |

W5 的费用计算口径：

```text
码头作业费 = 单价 × 当前订单数量
```

匹配优先级固定为：

```text
码头标准 node_id 的精确适用费率
-> 唯一已确认 operation_fee_region_code 映射下的唯一参考码头费率
-> 同一可追溯业务区域内地理距离最近的适用正式费率
-> manual_review
```

地域代理输出必须标为 `regional_proxy`，保留参考码头、映射依据、规则编号和版本，并声明它不是目标码头精确真实费率。找不到匹配、存在重复、映射未确认、贸易类型或品种不匹配、单位不支持时，Provider 返回 `manual_review`，不输出可计入金额。

客户自有码头经业务确认无需码头作业费时，Provider 返回 `not_applicable`，金额明确为 0，但不生成普通费用分项。该状态表示业务明确不适用，不是缺失数据补零；若同一请求同时匹配正数费率和不适用规则，则仍进入 `manual_review`。

## 5. `部分码头标签.json` 的当前用法

用户已确认：当前南港“码头作业费”先简化为只考虑 `入库` 费；该 JSON 中 `serviceFees.入库` 是单位费率，散粮单位为 `元/吨`。因此代码提供只读解析能力，将 `入库` 映射为候选 `码头作业费`。

边界：

- 该 JSON 默认仍是候选源，不自动替换正式 `南港码头作业费.csv`；
- `tradeType` 会被保留为正式匹配维度；
- 同一码头、不同贸易类型、不同品种允许存在不同费率；
- 名称未匹配标准节点时进入人工复核；后续别名治理按“名称字典 -> 腾讯地图 API -> 人工确认”的顺序推进；
- 审计入口：`python -B -m src.demos.port_label_rules_audit`；若未设置 `DATA_DIR`，可显式传入 `--data-dir data_REAL`。

名称字典优先阶段只接受保守匹配：去掉 `港`、`码头`、`港区` 或 `作业区` 后名称必须完全一致，并且所有可解析字典候选必须指向同一个既有标准节点。该匹配只给审计候选绑定 `node_id`，不会向节点注册表写入新别名。

剩余名称由用户在带本地 Tencent Key 的 PyCharm 环境运行：

```powershell
python -B -m src.demos.port_label_rules_audit --data-dir data_REAL --query-tencent --region "全国"
```

普通审计将待查询名称写入 `output/port_label_tencent_pending.jsonl`；显式执行 Tencent 后，候选写入 `output/port_label_tencent_review.jsonl`。两份文件分离，避免普通审计覆盖已抓取的候选证据。即使 Tencent 返回唯一 top1，也仍只作为人工确认材料。

仅在用户明确批准当前准入口径后，才可显式执行：

```powershell
python -B -m src.demos.port_label_rules_audit --data-dir data_REAL --apply-approved-w5
```

该命令准入已绑定标准节点的正数规则，把经确认的 0 元客户自有码头规则写为 `not_applicable`，并忽略其他未绑定节点；若正式表已经存在则拒绝覆盖。

同一审计命令还会生成：

- `output/w5_formal_data_admission_review.csv`
- `output/w5_formal_data_admission_review.md`

准入清单将候选分为“可申请准入、节点待确认、费用含义待确认”。默认情况下“可申请准入”仍不等于批准；2026-07-27 用户已明确批准当前批次正数候选和客户自有码头 0 元不适用规则进入正式测算，其他未绑定节点忽略。

## 6. 北港—南港集装箱船运价时效表

模板：`docs/data_templates/集装箱船运价时效.example.csv`

该表预留给北港—南港阶段的集装箱船真实数据。当前代码只加载和审计，不在
`leader_full_flow.py` 中自动构建集装箱船边；只有在后续接入已确认记录后，才可
按相同的 `TransportEdge -> nx.MultiDiGraph -> cost/time 独立搜索` 契约接入。

| 字段 | 类型 | 是否必填 | 说明 |
|---|---:|---:|---|
| `北港节点ID` / `北港名称` | 文本 | 名称必填 | 北港应优先使用标准节点 ID；名称用于展示和缺 ID 的人工复核 |
| `南港节点ID` / `南港名称` | 文本 | 名称必填 | 仅海港或海河一体港可作为北港—南港集装箱船终点 |
| `运输方式` | 文本 | 是 | 当前固定为 `集装箱船` |
| `包装方式` | 文本 | 是 | 当前固定为 `集装箱` |
| `订单数量单位` | 文本 | 是 | 首轮固定为 `箱`；`柜` 不自动换算 |
| `适用品种` | 列表 | 是 | 例如 `玉米；小麦` 或 `*` |
| `贸易类型` | 文本 | 是 | `内贸` 或 `外贸` |
| `报价` / `报价单位` / `价格类型` | Decimal / 文本 | 是 | 单价必须为 `元/箱 + unit_price`；整票总价必须为 `元 + total_price` |
| `航运总时效小时` | Decimal | 是 | 已确认的完整运输段总时间，不拆分等待、装卸和航行组成 |
| `确认状态` | 文本 | 是 | 仅 `confirmed` 可在后续构边；`manual_review` 只保留审计痕迹 |
| `维护日期` / `数据来源` | 文本 | 来源必填 | 用于最新记录选择与回溯 |

没有适用的、已确认的运价和航运总时效时，集装箱船边不得生成；不能借用散粮
散船、散粮驳船、铁路或汽运数据补齐。

| 字段 | 类型 | 是否必填 | 说明 |

| `package_type` | 文本 | 是 | 当前正式规则为 `散粮` |

| `unit_price` | Decimal | 是 | 当前散粮驳船单位费率，必须大于 0 |
| `fee_unit` | 文本 | 是 | 当前正式散粮规则固定为 `元/吨` |
| `trade_type` | 文本 | 是 | `内贸` 或 `外贸` |
| `bidirectional` | 布尔 | 是 | 往返费率一致时填 `是` |

## 8. 内河驳船运输时效表

模板：`docs/data_templates/内河驳船运输时效.example.csv`

| 字段 | 类型 | 是否必填 | 说明 |
|---|---:|---:|---|
| `origin_region_code` | 文本 | 是 | 起点区域编码，必须来自已确认区域映射 |
| `destination_region_code` | 文本 | 是 | 终点区域编码 |
| `duration_value` | Decimal | 是 | 大于 0 的运输时效原始值 |
| `duration_unit` | 文本 | 是 | `天`或`小时`，加载后统一换算为小时 |
| `time_scope` | 文本 | 是 | 当前简化模型固定为 `complete_segment` |
| `bidirectional` | 布尔 | 是 | 往返时效一致时填`是` |
| `source_type` | 文本 | 是 | 正式本地数据为 `real_data` |
| `source` | 文本 | 是 | 业务确认或维护来源 |
| `rule_id` | 文本 | 是 | 稳定规则编号 |
| `rule_version` | 文本 | 是 | 规则版本 |
| `maintained_at` | 日期/文本 | 否 | 维护日期 |

当前模型把船运时效直接视为对应航运段总时间，不拆分等待、装船、航行、卸船等组成。时效记录不限制包装方式；能否生成驳船运输边仍由港口能力、订单包装/品种和适用驳船航费共同决定。只有时效、没有航费时，可以返回时效结果，但不得生成零费用或可搜索的正式驳船边。
