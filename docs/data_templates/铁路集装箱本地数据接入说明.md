# 铁路集装箱本地 Excel 数据接入

真实业务 Excel、数据源清单和审计结果仅保存在本地 `DATA_DIR`，不得提交 Git。可提交的结构样例见 `铁路集装箱本地数据源清单.example.json`。

## 接入步骤

1. 将工作簿和本地数据源清单置于 `DATA_DIR`；清单中的 `workbook` 使用相对路径。
2. 每张业务表登记为独立 `table_type`：`station_master`、`trunk_rate`、`station_fee`、`time_region`，以及可选的 `direct_truck`、`customer_dedicated_siding`、`third_party_dedicated_siding`。
3. 在 `field_mapping` 中将规范字段映射到实际 Excel 表头；同一字段可提供多个表头候选。
4. 运行只读审计。只有 `confirmed`、精确北站—南站 OD、两端元/箱站费、完整时效和唯一标准节点均齐全的记录才会生成铁路干线边。

## 关键字段与口径

- `trunk_rate.base_freight_unit`：只接受 `元/箱`，或已确认 `元/组` 且 `group_box_count=2`；不折算 `柜`。
- `station_fee.fee_yuan_per_box`：上下站费必须按站点独立维护；缺失不可按区域、最近站点或散船规则代理。
- `time_region.duration_hours`：只表达北站—南站完整铁路运输段总时效；当前规则可由东北→福建/广东/广西表记录维护。
- 三类末端表各自独立：南站直达拖车、客户专用线、第三方专用线。缺表或缺费用/时效只会产生 `manual_review`，不会替换成别的方案。

## 数据边界

数据源清单只说明“文件如何读”；它不让未确认记录自动进入图。Excel Loader 不写回业务表、不调用腾讯地图，也不修改节点主数据。
